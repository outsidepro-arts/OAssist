# Участие в разработке OAssist

Обсуждения и документация — на **русском** языке. Сообщения коммитов и ветки — на английском ([Conventional Commits](https://www.conventionalcommits.org/)).

Порядок чтения для разработчиков и агентов: актуальные правила находятся в [`AGENTS.md`](AGENTS.md), состояние проекта и открытые вопросы — в [`MEMORY.md`](MEMORY.md). История решений сохранена в [`docs/history/README.md`](docs/history/README.md); открывайте по указателю только разделы, относящиеся к задаче. Не используйте исторические инструкции как текущие.

## Требования

* **Совместимый JDK (минимум 17)**, Android SDK (API 36), Gradle Wrapper проекта (`gradlew.bat` — не глобальный `gradle`). JDK выбирается через `JAVA_HOME` или `java` из `PATH`, без общего абсолютного пути и фиксации конкретной установки.
* Только **Kotlin**. Без Java, reflection-based DI и аннотационных процессоров, кроме Room (KSP).

## Сборка и проверки

```powershell
# Скомпилировать приложение и его модульные зависимости.
.\gradlew.bat :app:compileDebugKotlin
# Запустить юнит-тесты всех модулей.
.\gradlew.bat testDebugUnitTest
# Запустить Android Lint для модуля core:agent.
.\gradlew.bat :core:agent:lintDebug
# Собрать отладочный APK, если он нужен для задачи.
.\gradlew.bat :app:assembleDebug
```

Сборка использует штатные Gradle/Kotlin daemon и параллельное выполнение проектов. Необязательные синхронные обёртки и локальная диагностика OpenCode описаны в [`tools/README.md`](tools/README.md).

`clean`, `--offline` и `--no-build-cache` применяйте для конкретной задачи; они не требуются перед обычной сборкой и не диагностируют зависание агентского клиента.

## Требования к изменениям

Постоянные требования и чеклист готовности находятся в [`AGENTS.md`](AGENTS.md); принятое поведение, состояние проекта и открытые вопросы — в [`MEMORY.md`](MEMORY.md). Для UI-изменений выполняйте TalkBack-чеклист; для прочих изменений выбирайте подходящие модульные тесты и проверки Gradle. В описании результата указывайте, какие проверки действительно выполнены.

## Чего не делать

* Не коммитить секреты (`.env`, `local.properties`, ключи, `keystore/`) — проверяйте `git status`.
* Не менять `applicationId`/`namespace` (`ru.outsideproarts.oassist` зафиксирован).
* Новые зависимости добавлять по необходимости; часть артефактов Shizuku хранится в `vendor/maven`.
* Не коммитить без явной просьбы; коммиты — на английском.
