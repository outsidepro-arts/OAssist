# OAssist

![License: MIT](https://img.shields.io/badge/License-MIT-green.svg) ![Platform: Android 12+](https://img.shields.io/badge/Platform-Android_12%2B-3DDC84?logo=android&logoColor=white) ![Language: Kotlin](https://img.shields.io/badge/Kotlin-100%25-7F52FF?logo=kotlin&logoColor=white) ![Vibe Coded with AI](https://img.shields.io/badge/Vibe_Coded-with_AI-8A2BE2)

**OAssist** — клиент LLM-агента для Android с открытым исходным кодом, способный заменять стандартного системного голосового помощника. Приложение может вызываться поверх любого экрана стандартным жестом ассистента, выполнять действия на устройстве через системные интенты, сервис специальных возможностей (Accessibility) и привилегированные интерфейсы (Shizuku / Root), а также работать в режиме классического чата и обрабатывать контент из системного меню «Поделиться».

Проект ориентирован на личное использование, распространяется вне Google Play и разработан с жестким соблюдением стандартов доступности для программ экранного доступа (TalkBack).

> **О разработке:** Проект создан при помощи ИИ-агентов. Актуальные инструкции находятся в [`AGENTS.md`](AGENTS.md), действующее состояние проекта и открытые вопросы — в [`MEMORY.md`](MEMORY.md), подробная история решений — в [`docs/history/README.md`](docs/history/README.md). Архив сохраняет контекст прошлых решений; перед задачей достаточно прочитать относящиеся к ней разделы.

## Примеры запросов

| Вы говорите | Что происходит |
|---|---|
| «Поставь будильник на семь» | Модель понимает просьбу, будильник установлен |
| «Найди Сашу и напиши ему „я опаздываю“» | Контакт найден, SMS отправлена (с подтверждением) |
| «Включи фонарик» | Фонарик включён |
| «Открой ВК и напиши Антону привет» | Приложение открыто, сообщение написано |
| «Прочитай эту статью и скажи суть» | Страница прочитана, суть пересказана |
| «Запомни: я не ем сладкое» | Записано в память ассистента |

## Основные возможности

### Три режима работы

Для каждого режима настраиваются собственные провайдер, модель, системный промпт и параметры озвучки:

* **Ассистент (`ASSISTANT`)** — вызывается системным жестом помощника. Работает как компактная панель поверх текущего приложения или в режиме уведомления (без перекрытия экрана). При вызове может получать контекст текущего экрана и скриншот. Поддерживает непрерывный голосовой диалог и управление кнопкой гарнитуры (Play/Pause). При выборе экранного чтеца как канала озвучивания продолжайте диалог вручную кнопкой микрофона или гарнитуры. Изменение режима панели применяется после завершения текущей сессии и нового запуска ассистента.


* **Чат (`CHAT`)** — полноценный интерфейс диалога внутри приложения. Поддерживает хранение истории в локальной базе данных (включая вложения и вызовы инструментов), нечеткий поиск по диалогам, автоматическое именование чатов моделью, отображение цепочки рассуждений (reasoning) и статистику расхода токенов/стоимости.


* **Отправка (`SHARE`)** — точка входа из системного меню «Поделиться». Позволяет переслать текст и до четырёх изображений в новый или существующий диалог с моделью. Другие файлы не поддерживаются.
  Отправка доступна после загрузки истории и изображений. Переход в другой диалог останавливает текущий ответ и ждёт начатого сохранения; при ошибке записи история остаётся на экране с кнопкой «Повторить сохранение».



### Провайдеры и протоколы

Приложение не содержит жестко заданных списков моделей — перечень всегда запрашивается у сервера провайдера либо вводится вручную. Каталоги Gemini и Anthropic загружаются со всех страниц; ошибка загрузки не сохраняет частичный список. Модели с явно указанным несовместимым назначением (например, классификация или эмбеддинги) недоступны для чата. Если провайдер не сообщает назначение, модель остаётся доступной. Поддерживаются:

* **OpenAI-совместимые API** (`/v1/chat/completions` и `/v1/responses`).


* **Anthropic** (`/v1/messages`, extended/adaptive thinking по возможностям из каталога). Если нативный API не сообщает режим, при включённом «Мышлении» запрос останавливается с ошибкой настройки. Для proxy без metadata сохраняется прежний manual-режим; его совместимость зависит от proxy. Флаг «Мышление» не запрещает собственное мышление модели по умолчанию.
  Нативное adaptive-продолжение использует временный механизм `drop_block`: провайдер может исключить прежние рассуждения при изменении контекста. Приложение показывает отдельное уведомление; это может увеличить время и расход токенов. Сохранённые блоки не удаляются. Явный объект `thinking` в дополнительных параметрах остаётся пользовательской политикой и не дополняется автоматически.


* **Google Gemini** (`/v1beta/models/{id}:streamGenerateContent`).


* **OpenCode (Zen / Go)** — автоматическая маршрутизация протокола конкретной модели (через каталог models.dev, эвристику или ручной выбор).



Поддерживается передача изображений (Vision) и прямой аудиоввод (для моделей с поддержкой `audio_in`).

### Встроенные инструменты (50+ инструментов)

Агент может взаимодействовать с системой на трех уровнях доступа:

1. **Системные интенты и API (`intent.*`, `notify.*`, `web_*`):**
* Звонки, чтение журнала вызовов, поиск контактов, отправка SMS.


* Управление будильниками, таймерами и событиями календаря.


* Просмотр списка установленных приложений, их Activity и прямой запуск с параметрами.


* Чтение активных уведомлений, переход по ним, очистка и быстрый ответ (`RemoteInput`). Ответ передаётся целиком, включая пробелы; лимит — 500 кодовых точек Unicode. Более длинный или пустой ответ отклоняется без отправки. Успешная передача действия приложению не подтверждает доставку адресату.


* Управление медиа-плеерами и получение метаданных текущего трека (`MediaSession`), управление фонариком, громкостью, яркостью и режимом «Не беспокоить». На Android 15+ запрос DND меняет только правило OAssist: ручной режим и другие правила могут сохранить ограничения. Результат отдельно сообщает передачу запроса и наблюдаемый общий фильтр, без гарантии применения запроса к моменту чтения.


* Получение свежих координат геолокации и сводки состояния устройства (батарея, сеть, экран, звук).


* Поиск в интернете (парсинг выдачи DuckDuckGo, Google, Яндекс, Bing, Brave, Ecosia, Mojeek, Mail.ru) и чтение веб-страниц с конвертацией в Markdown (статический запрос или рендер через фоновый WebView).




2. **Сервис специальных возможностей (`ui.*`):**
* Снятие текстового слепка дерева элементов экрана (`ui_get_screen`), клики, долгие нажатия, ввод текста, скролл, свайпы, глобальные действия (Назад, Домой, Недавние).


* Просмотр и выполнение скрытых Accessibility-действий на узлах интерфейса (`ui_get_actions`, `ui_perform_action`).


* Создание скриншотов всего окна, заданной области или конкретного элемента интерфейса (с автоматическим скрытием панели ассистента на время снимка).


* Сервис работает строго пассивно: запрашивает дерево экрана только по команде инструмента и не мешает работе TalkBack.




3. **Привилегированный доступ (`shell_*` через Shizuku или Root):**
* Выполнение read-only shell-команд из белого списка, чтение и запись системных настроек (`system` / `secure` / `global`).


* Использование `input tap/swipe/keyevent` в качестве резервного механизма жестов.


* На MIUI/HyperOS приложение обнаруживает ограничение фонового запуска Activity и показывает команду для включения разрешения. Разрешение настраивается пользователем через Shizuku или ADB; автоматический обход не гарантируется.




### MCP, память и навыки

* **MCP-клиент:** подключение внешних серверов по протоколу Model Context Protocol (Streamable HTTP, версия 2025-06-18; поддержка Bearer-авторизации и пользовательских заголовков). Другие версии протокола при согласовании отклоняются с ошибкой.


* **Долговременная память ассистента:** агент может сохранять, читать и удалять факты о пользователе между сессиями. Эти данные хранятся приложением отдельно от проектных файлов [`MEMORY.md`](MEMORY.md) и [`docs/history/README.md`](docs/history/README.md).


* **Навыки (`Skills`):** подключаемые инструкции в формате Markdown, которые пользователь может создавать и переключать в настройках, а агент — подгружать по необходимости.



### Доступность (TalkBack) и работа с речью

Доступность для незрячих пользователей — базовое архитектурное требование проекта (соответствие WCAG 2.2 и практикам CVS Health Compose Accessibility):

* Все интерактивные элементы имеют корректные роли, описания состояний, заголовки секций и сгруппированные узлы фокуса; дублирование жестов кнопками и `CustomAccessibilityAction` обязательно.


* Два независимых речевых потока:


* **Озвучка ответа:** выключена, через системный TTS (с выбором движка, языка, голоса, скорости, тона и громкости) или напрямую в **экранный чтец (Screen Reader)**. В режиме экранного чтеца текст передается по предложениям через очередь анонсов (`TYPE_ANNOUNCEMENT`), не перебивая навигацию и не вызывая повторного чтения всего текста при обновлении стрима.


* **Нарратив работы:** проговаривание шагов агента (вызовы инструментов и их статус) отдельно от основного ответа, исключительно через экранный чтец.




* Приложение очищает Markdown-разметку перед отправкой текста в синтезатор речи.


* Настроен корректный перехват аудиофокуса (приглушение музыки при ответе, пауза медиа и приостановка речи TalkBack на время работы микрофона).


* Опциональное звуковое сопровождение событий агента (отправка, размышление, чтение/запись инструментами, запрос разрешения, готовность ответа).



### Безопасность и приватность

* **Хранение секретов:** все API-ключи, токены и заголовки шифруются через Android Keystore (`AES-256-GCM`) и хранятся в защищенном хранилище устройства (с поддержкой Direct Boot для работы ассистента на заблокированном экране). Секреты никогда не отображаются повторно в интерфейсе, не попадают в логи (используется redacting-логгер) и исключены из резервных копий (`allowBackup="false"`).
* **Резервное копирование:** экспорт сообщает об ошибке, если данные превышают ограничения формата; содержимое копии при этом не записывается. Лимит циклов инструментов сохраняется, а для старых копий без него используется значение по умолчанию.
* **Импорт настроек** заменяет сохраняемые в копии настройки: отсутствующие режимы сбрасываются к значениям по умолчанию, отсутствующие каталоги удаляются. Разрешения из копии не переносятся; отключённые на устройстве инструменты остаются выключенными. Новые MCP-серверы и серверы с изменённым адресом импортируются выключенными; ранее выключенные серверы не включаются. При ошибке или прерывании возможна частичная замена. Предупреждение остаётся в настройках: выберите тот же файл повторно и после успешного импорта введите секреты заново.


* **Контроль действий (Approval Gate):** все инструменты разделены по категориям и типу доступа (Чтение / Запись). Поддерживаются готовые пресеты безопасности и гибкие разрешения при вызове: разрешить однократно, на текущую сессию, запомнить выбор навсегда или отклонить.

## Технический стек и архитектура

* **Язык:** 100% Kotlin (Coroutines, Flow, `kotlinx.serialization`).


* **Платформа:** Android 12+ (`minSdk 31`, `compileSdk 36`).


* **UI:** Jetpack Compose + Material 3 (светлая и темная темы, контрастность AA).


* **Хранение данных:** Room (KSP) для истории чатов, Preferences DataStore для настроек и зашифрованных секретов.


* **Сеть:** Ktor Client 3 (SSE, политика автоматических повторов при сбоях сети и кодах 5xx/429, мониторинг подключения).


* **DI:** ручное внедрение зависимостей (`AppGraph`) без использования рефлексии и кодогенераторов вроде Hilt/Koin.

## Сборка проекта

### Требования

* **JDK:** совместимый с Gradle Wrapper и Android Gradle Plugin проекта (минимум 17). Wrapper использует `JAVA_HOME` или `java` из `PATH`; конкретная установка JDK в проекте не закреплена.


* **Android SDK:** API 36


* **Система сборки:** Gradle (через встроенный Gradle Wrapper `gradlew` / `gradlew.bat`)


### Основные команды

Компиляция и проверка кода (Windows):

```bat
.\gradlew.bat :app:compileDebugKotlin
.\gradlew.bat testDebugUnitTest
.\gradlew.bat lintDebug
```

Сборка отладочного APK:

```bat
.\gradlew.bat :app:assembleDebug
```

Готовый файл будет находиться в `app/build/outputs/apk/debug/app-debug.apk`.

Для сборки подписанного релизного APK (`:app:assembleRelease`) требуется файл `keystore.properties` в корне проекта (для генерации ключа предусмотрен скрипт `tools/gen-keystore.ps1`). Без него релизная сборка сформирует неподписанный пакет.

Подробности (обёртки запуска, релиз, тесты и локальная диагностика OpenCode) — в [`tools/README.md`](tools/README.md).

### Автоматические сборки GitHub

Workflow [`Android builds`](.github/workflows/android.yml) запускается на push в
любую ветку и на теги версий. Один push с несколькими коммитами собирает последний
коммит, как обычно в GitHub Actions. Ручные подтверждения и агент для CI не нужны.

Параллельно выполняются unit-тесты Debug и Release, тесты `diagnostic-lint`,
архитектурные проверки и lint обоих вариантов, проверки CI-скриптов и Android-тесты
на локальных для runner эмуляторах API 31 и 36. В AGP 9 unit-тесты Release включаются
параметром CI. Сетевой Android-тест включён явно; отсутствие результатов, ошибки и
пропущенные тесты считаются неуспешной проверкой. Это не заменяет проверку TalkBack.

После завершения всех проверок:

- Для любой ветки создаётся подписанный Debug APK в артефактах задания `apk`, даже
  если тесты или lint упали. Их результаты остаются видны как ошибки workflow.
- Для `master` проверенный Debug APK дополнительно публикуется в prerelease
  `updates-development` для самообновления. Сборки других веток в этот канал не
  попадают. APK, контрольная сумма и метаданные имеют неизменяемые имена;
  метаданные публикуются последними. При приближении к лимиту GitHub сохраняются
  200 последних полных наборов, более старые удаляются начиная с метаданных.
- Для тега Release APK выпускается только после успешных проверок. Подписанный и
  проверенный APK с SHA-256 сначала загружается в draft, затем публикуется в GitHub
  Releases. Повторный запуск может завершить оставшийся draft; опубликованный релиз
  автоматически не перезаписывается. Перед выпуском проверяется коммит тега.
- Ошибки сборки, подписи или проверки APK блокируют публикацию APK обоих вариантов.

Поддерживаются теги `v1.2.3`, `v1.2.3-beta.1`, `v1.2.3-rc.1`, а также суффиксы
`-beta`, `-beta1`, `-rc`, `-rc1`. Beta и RC помечаются как GitHub prerelease.
Для релиза `versionName` берётся из тега без `v`; nightly использует значение из
исходников. Неверный формат тега останавливает запуск до сборки.

Оба варианта используют `ru.outsideproarts.oassist` и существующий ключ приложения.
Администратор должен добавить в **Settings → Secrets and variables → Actions**:

| Секрет | Значение |
| --- | --- |
| `OASSIST_KEYSTORE_BASE64` | Существующий `.jks`, закодированный в Base64 |
| `OASSIST_KEYSTORE_PASSWORD` | Пароль keystore |
| `OASSIST_KEY_ALIAS` | Alias существующего ключа |
| `OASSIST_KEY_PASSWORD` | Пароль ключа, даже если совпадает с паролем keystore |

Новый release-ключ генерировать не нужно. Отпечаток сертификата закреплён в workflow
по ранее выпущенному APK. Подпись выполняется после Gradle; keystore и пароли не
передаются Gradle и не попадают в его кэш. Отсутствие секретов блокирует выпуск APK.
Защитите ветки, теги версий и изменения workflow: ключ используется для nightly
любой ветки. Локальная подпись через `keystore.properties` продолжает работать отдельно.

Общий `versionCode` равен `1000 + github.run_number`. Счётчик принадлежит одному
workflow для обоих каналов; повторный запуск сохраняет номер, неудачные запуски
оставляют пропуски. При замене workflow или переносе репозитория проверьте, что
следующий код выше всех распространённых APK, и при необходимости увеличьте
`VERSION_CODE_BASE`. Параллельные запуски могут завершаться не по порядку: более
поздно опубликованный старый APK не обновит уже установленный APK с большим кодом.
Nightly и release обновляют друг друга, поэтому увеличение кода учитывает оба канала.

Используется стандартное кэширование `gradle/actions/setup-gradle`; параметры Gradle
cache, daemon и параллелизма не отключаются. Готовые APK хранятся в артефактах и
релизах, а не в dependency cache. Срок хранения артефактов определяется настройками
репозитория. Отчёты тестов доступны в артефактах соответствующих заданий.
Android SDK и command-line tools явно подготавливает `android-actions/setup-android`:
наличие `sdkmanager` в исходном `PATH` runner не требуется.

## Настройка после установки

В разделе **Настройки → Обновление** доступны ручная и автоматическая проверка,
уведомления и выбор канала: стабильные выпуски, предварительные выпуски
(включая стабильные) или выпуски для разработчиков (включая оба вида релизов).
Автоматическая проверка включена по умолчанию, уведомления выключены. Проверка
выполняется примерно раз в сутки, 4 часа или 15 минут соответственно; Android
может задержать фоновые задания для экономии заряда.

До ручного выбора debug-сборки используют канал разработчиков, версии с beta/rc —
предварительный, остальные — стабильный. Ручной выбор сохраняется при установке
другого APK поверх приложения. Обновление загружается по кнопке и передаётся
системному установщику Android без удаления текущего приложения.

Пакет, подпись, версия и совместимость Android/ABI проверяются до загрузки;
после загрузки дополнительно проверяются размер, SHA-256 и сам APK. Для сборок
с известным CI-коммитом допускаются обновления на его потомков, а также релиз
того же коммита. Это консервативно исключает откат исходников при смене канала;
релиз из расходящейся ветки не предлагается. Ошибка GitHub не трактуется как
отсутствие обновлений. Старые публикации без метаданных обновления автоматически
не устанавливаются. Самообновление начинает работать с публикаций нового CI;
миграции пользовательских данных при изменении форматов по-прежнему обязательны.

1. **Провайдер и модель:** перейдите в `Настройки → Провайдеры`, добавьте профиль (укажите Base URL и API-ключ). Затем в настройках нужных режимов (`Чат`, `Ассистент`, `Отправка`) выберите провайдера и загрузите список моделей.


2. **Назначение помощником по умолчанию:** в системных настройках Android выберите OAssist в качестве цифрового помощника по умолчанию (`Приложения → Приложения по умолчанию → Цифровой помощник`), чтобы вызывать его стандартным жестом.


3. **Специальные доступы (опционально, в разделе `Настройки → Ассистент`):**
* *Поверх других окон* — для отображения компактной панели ассистента поверх приложений.


* *Сервис специальных возможностей (Доступ к экрану)* — для чтения экрана и выполнения нажатий/жестов агентом. (На Android 13+ при установке из APK может потребоваться предварительно включить «Разрешить ограниченные настройки» в системном экране «О приложении»).


* *Доступ к уведомлениям* — для чтения уведомлений, ответа на них и получения метаданных играющей музыки.


* *Shizuku / Изменение системных настроек* — для привилегированных команд и управления яркостью экрана.



4. **Для пользователей Xiaomi (MIUI / HyperOS):** чтобы система не блокировала открытие приложений и установку будильников из фонового режима оверлея, включите для OAssist «Автозапуск», установите контроль активности в «Без ограничений» и разрешите фоновый запуск через кнопку «Выполнить через Shizuku» в разделе `Настройки → Ассистент → Запуск в фоне` (либо через ADB: `adb shell appops set ru.outsideproarts.oassist 10021 allow`).

## English

**OAssist** is an open-source LLM agent client for Android that can replace the system voice assistant. It is invoked with the standard assistant gesture over any screen, performs on-device actions through intents, the AccessibilityService and privileged interfaces (Shizuku / Root), and also works as a classic chat and as a share-sheet target.

* **Three modes** — Assistant (overlay panel or notification mode, continuous voice dialog), Chat (local history with fuzzy search, auto-titling, reasoning stream, token/cost stats) and Share (text and up to four images from other apps; other files are not supported). Each mode has its own provider, model, system prompt and speech settings. A change between the assistant panel and notification modes takes effect after ending the current session and starting the assistant again.
* **Providers** — any OpenAI-compatible API (Completions / Responses), Anthropic (`/v1/messages`, extended/adaptive thinking), Google Gemini, and the OpenCode aggregator with automatic per-model protocol routing. No hardcoded model lists: models are fetched from the provider or entered manually. Vision and audio input supported.
  Anthropic thinking modes follow provider metadata. Native requests with the Thinking flag fail with a configuration error when the mode remains unknown; proxies without metadata retain legacy manual mode, subject to proxy support. The flag does not disable a model’s default thinking. Native adaptive continuation uses the temporary `drop_block` mechanism: a separate notice appears when the provider removes earlier reasoning after context changes. This may increase latency and token use; saved blocks remain intact. An explicit extra-body `thinking` object remains user-controlled and receives no automatic additions.
* **50+ built-in tools** across three privilege tiers: system intents (calls, SMS, alarms, calendar, apps, notifications, media, web search/fetch), Accessibility UI automation (screen snapshot, taps, text input, scrolling, screenshots, hidden node actions) and privileged shell commands via Shizuku / Root. Plus an MCP client, long-term memory and Markdown skills.
* **Accessibility-first** — full TalkBack support (WCAG 2.2), two independent speech streams (answer TTS or screen reader, work narration), audio focus handling, optional sound effects.
* **Security** — secrets encrypted with Android Keystore (AES-256-GCM), excluded from backups and logs; category-based approval gate with per-action, per-session and persistent grants.
* **Settings backup** reports an error when data exceeds the format limits, before writing backup contents. The tool round limit is preserved; older backups without it use the default.
* **Settings import** replaces the backed-up settings; missing modes use defaults and missing catalogs are removed. Permissions from the backup are not imported, and tools disabled on this device stay disabled. New MCP servers and servers with changed addresses are imported disabled; previously disabled servers stay disabled. If import fails or is interrupted, settings may be partly replaced. A warning remains in Settings: select the same backup again and re-enter secrets after a successful import.

Requires Android 12+ and a JDK compatible with the project Gradle Wrapper and Android Gradle Plugin (minimum 17). Build with the included wrapper: `./gradlew assembleDebug` on Unix-like systems or `gradlew.bat assembleDebug` on Windows. Interface languages: Russian (default) and English.
