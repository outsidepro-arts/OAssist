# Лимит шагов инструментов и плейсхолдер {steps_limit} — 2026-10-29

## Причина и диагностика

Пользователь: при выставленном «Без лимита» на действия агента на долгих цепочках
действий всё равно срабатывал лимит.

Причина — ручной дубль сборки `AgentLoop` в `MainActivity` (режим CHAT,
`sendMessage`): конструктор вызывался **без** `maxToolRounds`, поэтому действовал
дефолт `ToolPreferences.DEFAULT_MAX_TOOL_ROUNDS = 15`, игнорируя настройку.
SHARE и ASSISTANT шли через `AgentFactory.agentFor` (AppGraph), где
`maxToolRounds = prefs.maxToolRounds` передаётся корректно, — поэтому баг
проявлялся только в чате.

При сравнении дубля с `AppGraph.agentFor` нашлись ещё два расхождения того же
корня (copy drift): в чат не передавались внешние MCP-инструменты
(`resolveMcpTools()` пропущен при создании `ToolCatalog.createRegistry`) и
отсутствовал `fallbackFarewell` для терминального `bye`. Общий каталог
инструментов и fallback прощания по документации общие для всех режимов, так что
оба расхождения — тоже дефекты дубля.

## Исправление

- По решению пользователя ручная сборка `AgentLoop` в `MainActivity` удалена:
  чат берёт агента из общей фабрики `AgentFactory.agentFor(profile, mode)`, как
  SHARE/ASSISTANT. Лимит шагов, MCP-инструменты и fallback bye применяются
  единообразно; источник расхождений устранён.
- В `PromptRenderer` добавлен плейсхолдер `{steps_limit}` (`PromptInputs.stepsLimit`):
  положительное значение рендерится числом, `0`/отрицательное — явной фразой
  «без ограничений» / `unlimited` по языку, `null` (не передан) — пустой
  подстановкой по общему контракту рендерера.
- `AppGraph.buildSystemPrompt` подставляет в `{steps_limit}` текущий
  `maxToolRounds` из настроек инструментов (параметр `stepsLimit` позволяет
  передать уже прочитанный снапшот). Плейсхолдер работает во всех трёх режимах:
  промпт собирается общей функцией.
- В промпты по умолчанию (`app/src/main/assets/prompts/{ru,en}/{chat,assistant,share}.md`)
  добавлена строка с `{steps_limit}` и объяснением, что это лимит шагов
  (вызов инструмента и его результат — один шаг) **за каждый ход, а не за общую
  сессию**. Сохранённые пользовательские промпты не переписываются — плейсхолдер
  появится только в дефолтах и у тех, кто добавит его сам.
- Справка плейсхолдеров `mode_prompt_placeholders` (ru + en) дополнена
  `{steps_limit}` с описанием семантики («без ограничений», если лимит снят).
