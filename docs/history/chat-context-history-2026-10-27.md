# Сохранение контекста CHAT/SHARE — 2026-10-27

## Причина и происхождение

Регрессия введена коммитом `f4a7cfc` от 2026-10-16
(`feat(chats): saved dialogs with Room v2, drawer search and share flow`).
Раньше CHAT строил историю из экранных сообщений, включая ответы ассистента;
после перехода на `StoredTurn.modelMessages()` история стала состоять из USER + turn.
Поле answer сохранялось для интерфейса, но не использовалось при воспроизведении.

AgentLoop выдавал терминальный Finish перед callback onTurnMessages. CHAT записывал
StoredTurn прямо в обработчике Finish с ещё пустым turnTranscript; поздний callback
не изменял сохранённый объект. Терялись ответы и tool-пары между пользовательскими
ходами. Инструменты внутри текущего хода продолжали работать.

SHARE имел тот же порядок, но подставлял answer при пустом транскрипте: текст ответа
сохранялся, точные tool-пары терялись. Оверлей ASSISTANT добавляет историю непосредственно
из callback и этой ошибкой не затронут. Продолжение сохранённого диалога ассистента
через ChatScreen использует проблемный путь CHAT.

## Исправление

- Во всех трёх терминальных путях AgentLoop.stream транскрипт передаётся до Finish:
  обычный ответ, успешный bye, лимит раундов инструментов. Контракт указан у callback.
- StoredTurn.modelMessages при пустом turn и непустом answer воспроизводит сохранённый
  ответ как ASSISTANT. Непустой транскрипт остаётся единственным источником реплик;
  дубли и вымышленные tool-пары не добавляются. Миграция БД не требуется.
- Точные старые tool-пары не восстановимы из WorkEvent: в нём нет аргументов вызовов
  и идентификаторов. Сохраняется возможность восстановить прежние тексты ответов.
