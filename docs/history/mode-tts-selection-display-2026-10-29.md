# Отображение выбранного языка и голоса синтеза в режимах, 2026-10-29

Задача пользователя: при открытии окна режима (CHAT/ASSISTANT/SHARE) дропдаун
движка синтеза заполнен корректно, а дропдауны языка и голоса либо пустые, либо
показывают недостоверные данные; при сохранении других параметров сами параметры
синтеза не сбиваются. Нужно — корректное отображение выбранного языка и голоса.

Общий экран — `feature/settings/.../ModeConfigScreen.kt`, поэтому баг был во
всех трёх режимах сразу.

## Причины

Три связанных дефекта состояния TTS-выбора на экране режима:

1. **Гоночный одноразовый вывод языка.** `ttsVoiceLocale` вычислялся только
   внутри `LaunchedEffect(ttsEngine)` из `ttsVoice` *на момент завершения*
   `loadVoices`. Конфиг режима приходит асинхронно (сначала default с пустыми
   id, потом реальный — задокументировано в коде), поэтому `ttsVoice` часто
   устанавливался уже после завершения загрузки голосов, а эффект не
   перезапускался (движок тот же). Итог: язык показывал первую по сортировке
   локаль движка, сохранённый голос не находился в отфильтрованном списке и поле
   голоса отображало «Голос по умолчанию».
2. **Зомби-записи отменённой загрузки и разрушительная сверка.** `runCatching`
   вокруг `loadVoices`/`loadEngines` проглатывал `CancellationException` при
   рестарте `LaunchedEffect` (смена движка, ресинк конфига): отменённый эффект
   дописывал `voices = emptyList()` уже после того, как новый загружал реальный
   список — списки языка/голоса выглядели пустыми («либо пустые»). Плюс строка
   `if (ttsVoice.isNotBlank() && savedLocale == null) ttsVoice = ""` затирала
   сохранённый голос при пустом/неполном списке (загрузка не успела или не
   удалась). Что параметры в конфиге не «сбивались» при сохранении других
   параметров — заслуга ресинка: `LaunchedEffect(config, defaultPromptText)`
   восстанавливал `ttsVoice` из конфига при каждом изменении `config`.
3. **Выбранный язык негде хранить.** `TtsConfig` хранил только `voiceName`; язык
   был эфемерным фильтром списка. Для голоса «по умолчанию» выбор языка не
   сохранялся вообще и после переоткрытия заменялся первой по алфавиту локалью
   движка (у Google TTS — десятки локалей) — «недостоверные данные». Вдобавок
   `SpeechOutput.locale` никогда не выставлялся из конфига: `engine.language`
   всегда оставался `ru-RU`, выбор языка для голоса по умолчанию ничего не делал.

## Изменения

- `core/model` (`Providers.kt`): `TtsConfig.voiceLocale: String? = null` — язык
  выбора (BCP-47, `localeTag` голосов движка): для выбранного голоса его локаль,
  для голоса по умолчанию — язык синтеза. Поле необязательное: старые конфиги и
  бэкапы читаются как есть (`ignoreUnknownKeys` в обоих кодеках), миграция не
  требуется — формат отгружался, но новое поле добавляется только с дефолтом.
- `core/speech` (`SpeechOutput.kt`):
  - `applyConfig` выставляет `locale` из `config.voiceLocale` (при отсутствии —
    прежний дефолт `ru-RU` по политике языка STT/TTS): выбор языка теперь
    применяется к синтезу голосом по умолчанию и к предпрослушиванию примера;
  - хелпер `selectedVoiceLanguage(voices, voiceName, storedLocale)` — правило
    вывода отображаемого языка: локаль выбранного голоса (выбранный голос всегда
    несёт свой язык), иначе сохранённый выбор, иначе пусто (язык не выдумывается
    за пользователя).
- `feature/settings` (`ModeConfigScreen.kt`):
  - отображаемый язык — производное `effectiveVoiceLocale` из (список голосов,
    выбранный голос, сохранённый выбор), не отдельное состояние и не побочный
    эффект загрузки; в сохраняемый `TtsConfig.voiceLocale` пишется производное
    (легаси-конфиги без поля материализуются при первом сохранении);
  - загрузка голосов недеструктивна: только `voices = loaded`, выбор не
    сверяется и не сбрасывается; `CancellationException` пробрасывается, отменённый
    эффект состояние не пишет (то же для загрузки движков);
  - смена движка сбрасывает голос и язык явно в `onEngineChange` (имена голосов
    уникальны только внутри движка), а не побочно по факту отсутствия в списке;
  - значение поля «Голос» ищется по всем голосам движка, а не по отфильтрованным;
    при пустом/неполном списке показывается имя из конфига, а не «Голос по
    умолчанию».

Сохранённый язык/голос после правки отображаются сразу, без ожидания загрузки
списков; пустой список (загрузка не успела/не удалась) больше не искажает
выбор и не затирает его.

## Границы

- Пользователь подтвердил работу отображения (2026-10-29): выбранный язык и
  голос отображаются корректно, задача закрыта. Отдельные результаты пунктов
  ручного чеклиста и TalkBack-проход не сообщены.
- TalkBack-проход по дропдаунам языка/голоса не проводился (нет устройства):
  изменялись только значения полей, структура и семантика контролов не менялись.
- На устройстве: открытие окна каждого из трёх режимов с сохранёнными
  движком/языком/голосом (в т.ч. голос «по умолчанию» с выбранным языком),
  смена движка, сохранение других параметров без потери выбора, поведение при
  медленной/неудачной загрузке голосов.
