# Резервные способы ввода и доступа к настройкам — 2026-10-26

Пользователь выбрал сохранение всех существующих резервных способов. Новый путь
добавляется перед привилегированным исполнением; shell_exec, восстановление
AccessibilityService, обход чёрного кадра и исправление MIUI остаются прежними.

## Решения

- Для клика и удержания: действие узла → неподвижный жест AccessibilityService →
  прежний input tap/swipe через выбранный Shizuku/root. Оверлей скрыт на время
  координатной попытки. Long-click проверяет isLongClickable, а длительность
  нового жеста учитывает системный порог удержания.
- Для shell_get_setting/shell_put_setting: прямой Settings API в Dispatchers.IO,
  затем прежний исполнитель при ошибке или putString=false. Null и пустая строка
  при чтении — успешные значения. Группы подтверждений не меняются; минимальный
  уровень привилегий этих двух инструментов становится NONE.
- Отмена корутины не должна запускать привилегированный повтор.

## Независимый review

Reviewer нашёл один дефект: построение GestureDescription находилось вне защиты
новой попытки. При отклонении пути конструктором исключение могло завершить
инструмент, не вызвав старый резерв. Построение перенесено внутрь защищённого
dispatch-блока; добавлена JVM-проверка IllegalArgumentException с последующим
однократным вызовом привилегированного резерва.
