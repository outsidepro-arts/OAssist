# Упростение модели провайдера и универсальный роутинг протокола — 2026-10-28

## Контекст

Пользователь: тип провайдера из пяти значений (OPENAI_COMPAT/OPENAI_RESPONSES/
ANTHROPIC/GEMINI/OPENCODE) смешивает два понятия — проводной протокол и
нестандартности провайдера. Мотивация: найденный сторонний агрегатор моделей
подключается как OpenAI-compat (список моделей фетчится), но Gemini-модели через
него не работают — протокол жёстко зафиксирован типом.

Проверка первоисточников (openai-python, anthropic-sdk-python, ai.google.dev):
каталог моделей у всех API — последний сегмент `models`; версия (`/v1`, `/v1beta`)
— часть API-корня, а не ресурса. Форматов ответа два: `{"data":[{"id"}]}`
(OpenAI/Anthropic, у Anthropic есть `display_name`) и `{"models":[{"name":"models/x"}]}`
(Gemini).

Политика провайдера пересмотрена в ходе обсуждения (итоговое решение пользователя):
захардкодить популярные провайдеры пресетами, классический — «Своя настройка»,
OpenCode оставить бонусом с выбором эндпоинта.

## Решения

1. **Пресеты вместо «вкуса»**: `ProviderPreset = OPENAI | GOOGLE | ANTHROPIC |
   OPENCODE | CUSTOM`. Пресет — готовый рецепт: Base URL, протокол, каталог и
   авторизация под капотом (виден только API-ключ); `CUSTOM` («Своя настройка»)
   открывает все поля. Новый нестандартный провайдер — новый рецепт поверх общих
   механизмов, а не новый wire-протокол (их четверо, отличия — тела/SSE/auth).
2. Выборы у пресетов: Google — «Версия API» (v1beta / v1, под капотом задаёт
   baseUrl); OpenCode — «Эндпоинт» (Zen / Zen Go); OpenAI/Anthropic — ничего
   (всё детерминировано; протокол прячется под авто-резолв с фолбэком, per-model
   override остаётся в настройках режима). Переключатель каталога у пресетов
   убран — каталог у известных провайдеров известен.
3. **Пути едины**: baseUrl — корень API вместе с версией, как в документации;
   всё дописывается как есть. Каталог — `{base}/[catalogPath]` (`MODELS` |
   `NONE` = ручной ввод), формат ответа распознаётся lenient-парсером.
   `UrlStyle` (NATIVE/FLAT) и вставка версии в пути удалены; «Авто» в
   комбосписках нет, кнопка «Определить схему» не нужна.
4. **«Своя настройка»** дополнительно к прежним полям получила `extraBody`
   (JSON-объект: ключи мержатся поверх тел запросов к модели) и `catalogPath`;
   extra-заголовки получили UI-редактор (значения — в SecretStore). Переход
   пресет → CUSTOM показывает спрятанные значения, смена пресета не затирает
   имя/учётные данные.
5. Авторизация: `NATIVE` (key-based маппинг протокола) | `BEARER` |
   `API_KEY_HEADER` | `BASIC` (пара из SecretStore) | `NONE`; «Нативная» — один
   API-ключ. Легаси `basicAuthUserRef/PasswordRef` в бэкапах игнорируются.
6. Универсальный роутинг протокола: фикс профиля — одна попытка, авто
   (override → models.dev → эвристика) — фолбэк по 404/405 и маркерам Zen;
   per-model override действует во всех профилях.
7. **Миграция — один шаг из легаси `kind`** (единственный отгружённый формат;
   промежуточные формы сессии переписаны без миграций — правило записано в
   `AGENTS.md`): совпадение хоста и стандартного пути → пресет, иначе — CUSTOM
   с фиксом протокола и материализацией версии в baseUrl. Скрытый протокол
   пресетов при миграции = прежний фикс (поведение не меняется).

## Что сделано

- **core/model**: `ProviderPreset`, `GoogleApiVersion`, `OpenCodeEndpoint`;
  `ProviderProfile` — `preset/protocol/fetchScheme/authScheme/catalogPath/
  extraBody/apiKeyHeaderName/basic*` + `isValidExtraBody` для UI-валидации;
  `ProviderProfileSerializer` — миграция легаси `kind` (включая `OPENCODE_ZEN`)
  с host-совпадением и материализацией версии.
- **core/net**: общий `WireJson` — единый конфиг wire-сериализации тел
  (ContentNegotiation и мерж `extraBody`; разные конфиги разошлись бы телами).
- **core/provider**: `RoutingModelClient` (роутинг для любого профиля),
  `ModelCatalogFetcher` (`{base}/[catalogPath]`, lenient-парсер `data[].id` /
  `models[].name`, пагинация `pageSize=100&limit=1000`, `anthropic-version`
  на каталоге), `EndpointConfig.applyAuthHeaders` + `setBodyDecorated`
  (мерж `extraBody`: дубль ключа — дополнение побеждает), фолбэк протоколов
  по 404/405.
- **feature/settings**: форма пресетов (пресет-дропдаун, выборы Google/OpenCode,
  у пресетов — только имя/API-ключ/активность); CUSTOM — все поля, редактор
  extra-заголовков, `extraBody` с валидацией JSON; подсказка Base URL про версию.
- **app**: сохранение extra-заголовков через SecretStore.

## Проверки

- JVM-тесты по всему проекту без ошибок и пропусков: таблица миграции
  (host-совпадение всех kind, нестандартные base → CUSTOM, материализация версии,
  эндпоинты OpenCode, host-only OpenAI чинится), round-trip новых полей, lenient-
  парсер каталога и ошибка на неизвестный формат, `catalogPath`, мерж `extraBody`
  (дополнение побеждает, база сохраняется), auth-схемы, универсальный роутинг.
- `:app:assembleDebug`, `lintDebug` для core:model, core:net, core:data,
  core:provider, feature:settings, app — успешно.

## Границы проверки (не выполнено)

- Устройство/TalkBack: форма провайдера (пресет-дропдаун, выборы Google/OpenCode,
  условные поля секретов, редактор заголовков, `extraBody`) — ручной проход
  экранным чтецом не проводился.
- Реальный агрегатор пользователя: подключение как CUSTOM + авто-протокол
  (Gemini-модели через агрегатор) на устройстве не проверялось.
- Миграция реальных данных пользователя (DataStore/бэкапы) — покрыта только
  JVM-фикстурами; host-only base у легаси OpenAI-профилей при миграции
  «чинится» в пресет (прежние пути были нерабочими) — отмечено, но не проверено
  на реальных данных.
- Таймауты запросов и подтягивание имён моделей из models.dev для пресетов —
  отложено.

## Связанные решения

- Протокол модели не персистится результатом авто-резолва — только ручной
  override (`ModelInfo.protocol`).
- Правило миграций (только отгружённые форматы, одним шагом) записано в
  `AGENTS.md` → «Миграции данных».
