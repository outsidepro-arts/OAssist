# Терминальное прощание bye, 2026-10-27

Ветка `fix/runtime-prompts`, исходный коммит `4a261f7`. Пользователь сообщил о
двойном прощании раньше и преимущественно служебном «Сессия завершена» после
изменения общих промптов. Подтверждённая причина в протоколе: текст перед вызовом
попадал в комментарий к работе, затем результат bye отправлялся модели на новый
раунд. Озвучка могла содержать оба текста. По конкретным старым ходам трассы нет.

## Контракт

- Модель передаёт естественную реплику в обязательном строковом аргументе
  `bye({"farewell":"До встречи!"})`. Благодарность с новой просьбой не завершает
  разговор; самостоятельная благодарность не отменяет незавершённую задачу.
- AgentLoop доверяет завершение только успешному настоящему встроенному ByeTool,
  вызванному единственным инструментом раунда. Флаги провайдера, история, MCP
  и одноимённый другой инструмент не создают сигнала закрытия.
- Смешанный пакет и повторный bye отклоняются до побочных действий. Каждому
  tool call соответствует ошибочный результат, модель может исправить вызов.
- Ошибочный JSON и нестроковый farewell не завершают сессию. Для совместимости
  отсутствующий/пустой строковый аргумент берётся из накопленного текста раунда,
  затем из локализованного ресурса, который AppGraph внедряет по языку промпта.
  В прямой фабрике без текста и fallback — ошибка без закрытия.
- Успех публикует один основной Content с признаком терминального прощания и
  Finish(closeSession=true); нового запроса к модели нет. Комментарий этого раунда
  и служебные события bye не озвучиваются через нарратив. История сохраняет
  связанные tool calls/results, reasoning/replay и одну финальную реплику; usage
  передаётся один раз. Отключённый/запрещённый вызов не закрывает сессию.
- Хост больше не выставляет pendingBye по имени ToolCall. Терминальный ответ
  отображается сразу, обходит StreamSpeaker и после Finish подаётся по предложениям
  через speakWhenReady, затем ожидается awaitIdle. Это сохраняет один основной
  ответ и очередь отдельных announcements для SCREEN_READER.
- Общий предел 30 секунд охватывает готовность движка, подачу и ожидание очереди.
  По таймауту stop вызывается один раз, показывается локализованная ошибка,
  сессия закрывается без повторной подачи. Внешняя отмена coroutine пробрасывается.
  Выключенная озвучка не считается ошибкой.

## Очередь речи

- Receipt регистрируется синхронно до асинхронной постановки объявления. awaitIdle
  ждёт снимок уже принятых TTS/SR-подач, не захватывая будущие.
- Stop/shutdown снимают старые receipts и меняют поколение, чтобы поздняя старая
  подача не попала в новую очередь. Отмена ожидающего не отменяет общие receipts.
- TTS освобождает ожидание на onDone/onError/onStop, немедленном ERROR и исключении
  speak. speakWhenReady возвращает false, если запрос не принят.
- Независимое ревью выявило гонку speaking: отменённый старый enqueue мог сбросить
  флаг новой очереди в межфразной задержке. Добавлены проверка поколения и владения
  worker, видимость ссылки worker и детерминированный регрессионный тест. Повторное
  ревью подтвердило исправление.
- awaitIdle означает обработку или снятие запроса, а не успешное слышимое
  воспроизведение. Async TTS onError освобождает ожидание, но Boolean приёма не
  становится отчётом о воспроизведении. Для TalkBack доступна передача объявления,
  callback фактического окончания речи отсутствует. Типизированные результаты
  воспроизведения не добавлялись; автоматического повтора финальной фразы нет.
